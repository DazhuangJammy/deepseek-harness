# Agent Note: 桌面端应用菜单中的标准编辑角色

Status: implemented

[English](2026-09-12-desktop-edit-menu-roles.md) | 中文

## 问题

Electron 外壳安装的应用菜单里只有它自己的命令：桌面插件、检查更新、退出。macOS 的标准编辑快捷键由携带 Electron 编辑角色的菜单项派发，因此没有「编辑」菜单时，渲染进程的文本框收不到复制、剪切、粘贴与全选。打包后的应用无法把 API Key 粘贴进设置字段，也无法从对话里复制文本。

## 决策

应用菜单现在带有第二个顶级「编辑」子菜单，其菜单项使用 Electron 的角色——`undo`、`redo`、`cut`、`copy`、`paste`、`selectAll`——标签取自外壳字典，因此两个随附语言都能命名它们，并由角色提供各平台的快捷键。菜单其余结构不变：应用菜单仍排在第一位，外壳仍然不拥有其他顶级菜单。

## 后果

- 标准编辑快捷键在外壳打开的每个窗口中都可用，包括插件管理器自己的输入框。
- 菜单语言跟随外壳语言，而不是 Electron 自带的角色标签本地化，因此整条菜单栏使用同一种语言。
- 新增菜单项现在需要两个外壳字典都提供键；否则语言测试的键齐全检查会失败。
- 渲染进程保持不变：没有任何页面为实现剪贴板而自行实现处理逻辑。

## 考虑过的替代方案

**使用 Electron 内置的 `role: 'editMenu'`。** 一行即可提供整个「编辑」菜单，但它的标签来自 Electron 自身的翻译而非外壳字典，因此应用菜单与「编辑」菜单可能在同一菜单栏里语言不一致。

**保持菜单不变，在渲染进程里处理快捷键。** 浏览器应用本来也收不到这些命令，而且网页无法为文本框实现原生剪贴板；角色是唯一受支持的途径。

**把角色加进既有的应用菜单，而不是单独的子菜单。** macOS 把第一个菜单保留给应用自身的命令，其菜单项并不是编辑命令的惯用位置；单独的「编辑」菜单符合其他 macOS 应用用户的预期。
