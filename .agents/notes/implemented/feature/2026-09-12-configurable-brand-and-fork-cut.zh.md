# Agent Note: 可配置的桌面品牌与分支截断

Status: implemented

[English](2026-09-12-configurable-brand-and-fork-cut.md) | 中文

## 问题

浏览器品牌插件只渲染一套固定的官方标识与名称，并由 `DSH_CLIENT_BUILD_PROFILE=official` 决定是否注册它们。身份不同的部署只能不挂载该包、再自己编写一个占位包，因为这个随包发布的插件没有提供任何配置界面。空白会话首屏始终显示自己的动态标识和它自己的 `hero.headline` 文本，与侧边栏无关，因此部署方无法在两个界面上呈现同一个品牌。

创建分支时，子会话日志从 `boundary.seq + 1` 处截断。活动会话中的序列值是连续的，但没有任何机制保证观察数组以序列值为下标：准备态或冷读可能携带非下标化的序列值，此时该截断会把下一轮的用户输入一并留在分支里。

## 决策

插件拥有持久化的 `ui-brand-official` 设置命名空间，其 `BrandSettingsSchema` 包含 `enabled`、`name` 和 `icon`。Host 侧在 `settings` 服务被组装时注册该 schema。浏览器侧把 `SettingsScope` 绑定到该命名空间，并向它注册的每个占位者发布控制器接口——`brand` 与 `editor` 两个快照存储，以及 `edit`、`save`、`reset`。

设置 → 插件渲染一张品牌卡片：启用开关、名称输入框、图标地址、本地图片上传、未保存标记、保存与重置。保存写入一次变更，设置全部三个键，并对名称与图标做首尾去空白；重置则取消设置这三个键，让 schema 默认值回归。写入失败会置起卡片的失败状态，而不是报告成功。

插件只在品牌确实适用时才占用槽位。官方构建 profile 在没有配置任何取值时也保留侧边栏中随包发布的标识与名称，因为该 profile 发布的就是官方身份。其他宿主都把每个槽位留给声明它的包，直到设置为该界面携带了取值；因此本地构建保留自己的标识与构建标签，而不会悄悄改用官方 wordmark。存储订阅随设置变化注册或释放每个占位者，因此一旦填充槽位的取值被清空，该槽位立刻回到声明包的回退。

对话首屏保留自己的界面：本次改动在既有的 `conversation.hero.brand.mark` 之外新增 `conversation.hero.brand.name` 槽位，`EmptyHero` 以 `hero.headline` 文本作为它的回退渲染。两个首屏槽位都没有官方 profile 例外，因为它们各自的回退本来就是随包发布的呈现。

分支创建在 Host 命令控制器与浏览器 fixture 中都改为按匹配事件在数组中的位置（`indexOf(boundary) + 1`）确定截断点。

## 后果

- 部署方可在设置 → 插件中修改自己的品牌；这些值持久保存、对每个窗口生效，且无需重新构建浏览器或改动装配清单。
- 取值留空或品牌关闭时，各界面保留原有的回退，因此只启用功能而不填写内容不会带来任何变化。
- 空白会话首屏与侧边栏可以共用同一个上传图标，其他占位包也仍可占用同样的槽位。
- 插件现在需要 settings、locale、settings-plugin 与 conversation 这几个客户端服务；其包清单与依赖集相应增长，`docs/config-catalog.md` 记录了新的命名空间。
- 分支创建不再假定序列值等于数组下标。
- 本地构建在有人配置品牌之前保留自己的侧边栏标识与构建标签，因此对从未启用该功能的部署而言这次改动是不可见的。
- `DSH_CLIENT_BUILD_PROFILE` 仍然决定未组装 `settingsScope` 的宿主是否注册任何内容，现在还决定未配置品牌的侧边栏是否保留随包发布的品牌。

## 考虑过的替代方案

**保留 profile 开关，自定义身份一律另写替代包。** 否决，因为这条既有路线让每次改品牌都等于复制一份插件并重新构建客户端，而设置服务及其插件界面本来就能承载按部署持久化的取值。

**无条件注册每个占位者，在其内部渲染回退内容。** 否决，因为标识与名称是两个取值相互独立的槽位；总是注册的占位者会从声明该槽位的包手中夺走槽位，于是本地构建会显示官方 wordmark，而不是它自己的构建标签。

**把品牌存进客户端存储而不是设置服务。** 否决，因为这些取值要跨越单个浏览器 profile，并且必须对每个窗口生效，而这正是持久化设置段提供的能力。

**按序列值而不是对象标识查找边界。** 否决，因为被匹配到的事件本身就是应当在其之后截断的那个数组元素，再按序列值查找一次只会多出一次搜索，却不改变结果。
