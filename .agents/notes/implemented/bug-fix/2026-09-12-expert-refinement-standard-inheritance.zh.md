# Agent Note: 专家提示词优化完整继承标准模式

Status: implemented

[English](2026-09-12-expert-refinement-standard-inheritance.md) | 中文

## 问题

专家提示词优化虽然选择了 `standard` preset，但同时又设置了专用 persona、请求大小上限、输出 token 上限与截止时间。这些覆盖可能会拒绝或停止原本可由标准 Agent 的压缩、模型路线、重试策略与普通运行时长处理的工作，因此选择该 preset 并没有保留它的完整行为。

## 决策

Host 以进程内一次性子级启动优化，传入 `agentPreset: standard`，并且只提供专家任务、已记录的证据上下文、结构化输出 schema 与取消信号。它不会覆盖 persona、Agent 选项、请求大小、重试策略或运行时长。因此子级会获得完整标准组装，所选模型路线则继续决定提供方、模型、推理强度、输出策略与请求重试。调用方取消与 parent 维护仍是优化专用的仅有提前停止来源。

一次性运行只表示它拥有一个已提交任务及其结构化结果，不会定义子级的能力。在整次运行中，标准 preset 仍提供其完整提示词分区、工具、skill、上下文压缩、目标、子 Agent、工作流与其他已注册行为。

## 考虑过的替代方案

**调高优化专用上限。** 否决，因为任何独立数值都可能低于标准路线，或者终止标准 Agent 仍认为有效的工作。删除重复策略可以保留单一决定方。

**把优化改为可继续子级。** 否决，因为优化只有一个任务和一个结构化结果，现有进程内一次性驱动器已经能够挂载完整标准 preset，并负责结果捕获与完全停稳后的清理。可继续性会增加第二套编排生命周期，但不会增加标准模式能力。

**在优化协调器里重试终态结果。** 否决，因为请求重试与上下文溢出恢复已分别属于所选路线和标准压缩插件。协调器重试会建立第二套策略，并且可能重复已完成的工具工作。

## 后果

优化不再拥有比它启动的标准子级更短的 token 额度、输入额度或墙钟时长。模型提供方仍可以执行其已配置的上下文与输出上限，但专家工作流不会再增加更严格的限制或替换其恢复行为。浏览器「停止」操作与 parent 拆除仍会通过同一信号路径取消子级。

聚焦工作流覆盖会验证启动请求选择 `standard`，并且没有 persona 与 Agent 选项覆盖。现有无密钥专家优化 snapshot 继续通过已发布 profile 固定模型可见的 skill 任务。
