# Agent Note: 聊天文件能力

Status: implemented

[English](2026-09-11-chat-file-capabilities.md) | 中文

## 问题

聊天模式可以接收与其他模式相同的上传文件，但文件会以保存路径句柄进入模型，而不是以内联字节进入。聊天模式的空工具集无法读取该句柄。由于不存在匹配的工具 schema 或执行器，模型可能把学到的 shell 调用格式作为普通文字输出。

聊天专家继承了同一个缺口。另建文档摄取链路会让聊天模式与标准模式的文件行为不同，也会重复已有执行路径。

## 决策

随附的 `chat` preset 挂载与 `standard` 处理上传文件时相同的平台 shell、文件系统、图片读取与文件系统搜索工具插件。所选模型路线支持图片时，图片附件继续通过模型 adapter；文件句柄可以使用已挂载工具，并遵守与标准模式相同的 sandbox 和 approval 策略。

聊天模式仍不加载 skill 发现、项目指令、运行时上下文、压缩、规划、目标、subagent、工作流、Web 工具和显式交付工具。完整对话 persona 与 Session transcript 行为保持不变。

受管专家组装包含相同的文件工具行。专家挂载前，agent-preset 服务会恢复其受管组装，让旧版本创建的专家获得当前聊天能力，同时不改变提示词版本或元数据。

## 考虑过的替代方案

**新增独立文档摄取能力。** 否决，因为要求是与标准模式保持一致，包括相同的支持格式与 shell 提取路径。第二套解析器会拥有不同的格式覆盖与失败行为。

**只挂载 UTF-8 `read` 工具。** 否决，因为上传的 Word 与 PDF 不是 UTF-8 文本。现有 `read` 工具无法提取这些文件，而标准模式使用 shell 和文件系统工具处理它们。

**挂载完整标准 preset。** 否决，因为文件能力一致不要求编码指令、skill、规划、委派、Web 访问、目标或工作流。这些能力会改变聊天模式的用途与请求成本。

## 后果

聊天请求会携带文件工具 schema 与指引，因此比空工具请求占用更多上下文。聊天模式可以执行同一 sandbox 与 approval 策略允许的 shell 命令和文件修改；该模式默认用于对话，不是安全边界。

[较早的聊天决策](2026-08-21-tool-free-chat-preset.zh.md)继续负责完整 persona、transcript 与未加载的非文件能力。本决策只取代其中的空工具集规则，以及断言请求头不含 `tools` 的快照。
